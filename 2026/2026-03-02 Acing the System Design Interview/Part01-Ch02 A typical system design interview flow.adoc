=== A rough guide to a system design discussion

1. Clarify the requirements. Discuss tradeoffs.
2. Draft the API specification.
3. Connections and processing between users and data
4. Design the data model. 
5. Discuss possible analytics. (Logging, monitoring, and alerting)

*Other*

6. Discuss failure design, graceful degradation, monitoring, and alerting. Other topics include bottlenecks, load balancing, removing single points of failure, high availability, disaster recovery, and caching.
7. Discuss complexity and tradeoffs, maintenance and decommissioning processes,
and costs.
